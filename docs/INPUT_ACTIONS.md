# The game's input actions: default keys and who asks

Generated by pipeline/input_actions.py from the analysed build (6A995428); its docstring says what it reads. The
columns: the context word (0x1036CF60); the three default key bindings (0x1036D6B0) with their conditions (Shift, Ctrl,
Alt, Ctrl+Alt; Ctrl-or-Alt+opt5C: Ctrl or Alt held and the option byte 0x1036CF5C set; no-Shift; not-typing: not while
the chat line is in mode 4 or 5; no-Ctrl/Alt); the handler (0x1036DB18: the virtual pad's answer, docs/INPUT.md 3b);
the functions whose call pushes the action as a constant, with the kind asked (0 trigger, 1 pressed, 2 take trigger, 3
take pressed, 4 held, 5 released). The bindings are the file's defaults: the game's key configuration rewrites them at
run time. Calls that pass the action in a register are not listed per action: NetCellFont_UpdateHoldState4 x2, TaskAndTextArgs_ToggleOnKey x1, 10125360 x1, 1013A5B0 x1, TargetMenu_FindActiveCommand x1, TextInputFiles_ApplyKeyAction x1, TextInputFiles_ShortcutCheck x1.
"Pad / mouse" is what the handler answers, read from its code (docs/INPUT.md 3b, 3c): a pad bit of the virtual pad, a mouse
button, or and/or of other handlers and keys ("held": asked as held whatever the kind asked).
A name is the repo's name for the function (docs/NAMES.md); an address is a function without one. What an action does
in play is stated only where docs/INPUT.md has read it. The tables hold 188 entries (the binding table, 3 words each,
ends where the handler table starts: 0x1036D6B0 + 6*188 = 0x1036DB18); entries with nothing in them are left out
(35, 187).
